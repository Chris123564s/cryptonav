## CryptoNav 加密币导航网站

### 用户提供了 CoinGecko Demo API key，并问 Cloudflare 环境变量该选 Text 还是 Secret
结论：**选 Secret（加密）**，不要选 Text（明文）。
依据（查 Cloudflare 官方文档 `pages/functions/bindings`）：
- Secret：加密存储，保存后不可再查看；在 Pages Functions **运行时**通过 `context.env` 可读取
- Text：明文，任何有项目权限的人都能看到；额外支持**构建时**可见
- 我们的代理函数是在运行时读 `env.COINGECKO_API_KEY`，不需要构建时可见 → Secret 完全够用且更安全
- **两者都是 Bindings，新增/修改后对已有部署无效，必须重新部署才生效**
  （Secret 文档原话：must be done "before a deployment" that uses those secrets）
- 本地开发放 `.dev.vars` / `.env`，且必须加进 .gitignore

### ⚠️ 重大事故：git 对象库损坏 + 恢复全过程（值得记住）
起因：`git pull --rebase origin main` 被工具超时 SIGTERM 打断（命令跑太久）。

现象：
- `git log` / `git status` 全部报 `fatal: bad object HEAD`
- `refs/heads/main` 指向的本地专属提交 `20ee5ef` 对象丢失
- `.git/rebase-merge/` 留下**空目录**，让 git 以为 rebase 仍在进行
- `git fsck` 显示 `in-pack: 1160`（历史明显缺失）+ 多处 `broken link`
- 根因：`.git/objects/pack/` 里 3 个 `.idx` **只有 1 个 `.pack`**，另两个 `.pack` 文件消失

恢复步骤（全部非破坏性，最终零损失）：
1. **先把改动文件 cp 到 `.git-backup-files/`**（这是最关键的一步）
2. `rmdir .git/rebase-merge`（空目录用 rmdir，只对空目录生效，天然安全）
3. `git fetch origin main` → **意外把丢失的 51b181f 对象补回来了**（远端有的对象能拉回）
4. `git update-ref refs/heads/main <51b181f 完整 SHA>` 把 main 指回存在的提交
5. `git reset --mixed HEAD` 重建索引 → 只剩预期的 2 个文件显示为已修改，无虚假差异
6. `cmp -s` 逐字节比对备份与工作区文件 → 确认改动完好
7. 重新 commit（新 SHA b4c63cf）+ push

**完整修复（最终 `git fsck` 零错误）：**
8. `git multi-pack-index write` 重建 MIDX
   —— 顺带发现 fetch 其实已经把丢失的对象打包成了新 pack `pack-83b913a`，
      所以真正缺的只有那两个孤立 .idx 对应的旧包，历史一个没丢
9. `git reflog expire --expire-unreachable=now --all` —— 清不掉指向 20ee5ef 的残留
10. `git reflog expire --expire=now --all` —— 全清，fsck 彻底干净

验证：83 个提交可完整遍历（最早 `3f991b8 feat: CryptoNav 加密币导航站`）、
status 干净、push 正常、回归测试 23/23。

结论与教训：
- **本地专属、未推送的提交（20ee5ef）在对象丢失后无法恢复**，只能靠文件内容备份重做
- 远端已有的对象可以通过 `git fetch` 拉回，所以先别急着重 clone
- 长耗时 git 操作（pull --rebase + push）要设长超时或放后台，被 SIGTERM 打断可能损坏对象库
- `fsck` 报 "failed to load pack in position N" 多半是**孤立 .idx（无对应 .pack）+ 陈旧 MIDX**，
  不代表数据真丢；先用 `git rev-list --count HEAD` + 抽查 `git cat-file -e` 确认历史完整性，
  再决定要不要修，别上来就重 clone
- 修完一定要让 fsck 归零，否则今后的 fsck 报错会被当成噪音忽略，失去预警作用

### 沙箱环境注意
- `.git/refs/remotes/` 在这个沙箱不持久（fetch 成功但 `origin/main` 查不到），
  必须用 `FETCH_HEAD` 替代 `origin/main` 做比对（`git rev-list --count FETCH_HEAD..HEAD`）
- 本回合曾出现瞬时 `schannel: failed to receive handshake, SSL/TLS`，重试即可
- **合并分叉优先用 `git merge`，不要用 `git pull --rebase`**（rebase 被打断就是本次事故起因）
